Get started

Open the workspace to explore a twelve-channel, two-minute synthetic recording at 256 Hz. It contains no patient data and works without the EEG backend. Select channels in the sidebar, use +/− to zoom, drag to pan, and use the bottom timeline to move through the recording. Home resets the view; arrow keys pan, Shift + left/right inspects adjacent samples, and up/down selects channels when the plot is focused.

To use an EDF, start the local backend and development frontend from your NeuroScope checkout. Use Python 3.12 and the Node version specified by .nvmrc. Install dependencies once: 

python3.12 -m venv .venv-backend
.venv-backend/bin/python -m pip install -r backend/requirements.txt
npm ci

In separate terminals:

# Terminal 1: localhost-only EEG service
.venv-backend/bin/python -m backend.neuroscope_api

# Terminal 2: development frontend
npm run dev

Open the local URL printed by Vite, go to /app, and choose Upload Recording. The backend launcher binds to loopback; do not expose it through a public host, tunnel or proxy. The backend currently supports macOS/Linux. EDF uploads are intentionally disabled in production builds; a static preview offers the synthetic demo only.

Signals, samples and timing

NeuroScope preserves original channel names, native channel sampling frequencies and calibrated measurements. Voltage values are expressed in microvolts (µV). Mixed-rate channels retain their own clocks; they are not represented as if acquired on a common sample grid.

Zoomed-out views use extrema envelopes to retain peaks. Exact inspection retrieves the original sample. The inspector formats amplitude to 0.01 µV and time to six decimal places; use CSV when you need full-precision exported values. A narrow display range can clip peaks, with a visible warning. No new filters, re-referencing, montage or signal analysis is applied.

Unprefixed voltage channels may be treated as EEG candidates. A label alone cannot establish a channel’s physiological meaning. The introductory brain and electrical pathways are artistic and are not linked to an uploaded recording.

Keep observations located

Create a point or interval with the annotation controls or by selecting on the waveform. Channel-linked boundaries snap to that channel’s native samples. Recording-wide annotations use seconds. Intervals include their start and exclude their end.

Annotations are held in the current session. Refreshing, leaving the workspace, switching recordings, or EDF expiry can discard them. Export JSON before you leave. To restore, load the matching recording and import the JSON. Review compatibility and conflicts before confirming. Missing file identity requires explicit confirmation; a known different fingerprint is rejected. A fingerprint is not an authenticated signature.

Three formats, three purposes

PNG — the visual record
A labeled visualization of the current window with visible channels and annotations. The export may expand the amplitude scale to fit peaks, and labels that scale. It is a picture, not raw data.
CSV — original measurements
Long-form rows contain channel identity, original sample index, recording-relative time in seconds and amplitude in µV. Selected channels are exported in selection order. Each uses its native clock; different rates produce different row counts. No display downsampling, filtering or interpolation is applied.
JSON — portable annotations
Recording compatibility information and point/interval annotations, including native anchors where applicable. It does not contain or reconstruct the original EDF.

Supported formats and limits

Supported: classical EDF and continuous EDF+C with known lengths, unique ASCII channel labels and recognized voltage units. Unsupported: EDF+D, BDF, unknown record counts, duplicate channel names, unrecognized units and invalid calibration. Unsupported files are rejected rather than silently repaired.

  • Default upload limit: 64 MiB per file.
  • Default temporary storage: four recordings, 256 MiB total, one-hour lifetime.
  • File structure: up to 256 source signals, eight distinct available EEG rates, 100,000 data records and 24 hours. Other per-record and annotation limits also apply.
  • EDF view: up to 32 selected channels per page; initial selection is limited to twelve.
  • CSV export: at most 60 seconds, 32 channels, 250,000 rows and 16 MiB.
  • Windowed retrieval and display limits prevent loading whole large recordings into browser memory. Busy or oversized requests return an explicit error.

These are the standard local configuration limits, not a promise that every file below the size cap is supported. See backend/README.md in the checkout for the complete contract and configuration.

Current local data handling

The synthetic demo contains no patient data. In local development, uploaded EDF bytes are sent to a service on the same computer and stored in private temporary files outside public directories. The application has no cloud recording storage or authentication.

The default lifetime is one hour. Expired recordings are rejected on access and cleaned up periodically; manual deletion and graceful shutdown remove temporary copies. After an unclean exit, copies may remain until the next backend startup. This is deletion, not guaranteed secure erasure or encryption at rest.

Patient identity fields are withheld from API responses and access logging is disabled by the launcher. That does not anonymize the original file. Channel labels, annotations, screenshots and downloaded exports can still contain sensitive information. Other local processes are not isolated by an account system.

The service is not designed for public, hostile or multi-user traffic. A future hosted service requires a separate privacy and security review. Local handling statements must not be treated as guarantees for a future deployment. This page documents current behavior; it is not a hosted-service privacy policy.

Independent data-integrity checks

Phase 3D.1, baseline 22fff1f, validated in commit f64f16b. A separately implemented standard-library EDF reader compared raw digital bytes and exact rational header calibration with NeuroScope’s outputs, independently of the MNE decoding path.

  • Six accepted cases: two public EEG Motor Movement/Imagery files, a 22-hour Sleep-EDF file, a 256-channel fixture, a mixed-rate fixture and a file just below the 64 MiB limit.
  • Corrupted and oversized files were rejected as expected.
  • 270,361 native sample values compared; largest measured amplitude difference: 5.684341886080802e-14 µV.
  • Largest API CSV timestamp difference: 6.984919309616089e-12 seconds. Discrete sample-index mismatches: zero.
  • 115,915 browser draw points and 3,216 downloaded CSV rows checked against original byte calculations. Annotation restoration and actual PNG correspondence were also tested.
  • Fractional-rate final-viewport navigation and long-duration labels were corrected.

This is finite coverage, not proof for every vendor format or every sample in every recording. The reference was separately implemented within the project; this was not an audit by an independent institution. Full methods, file checksums, numerical errors, reproduction commands and limitations are in SCIENTIFIC-VALIDATION.md in the project checkout.

Public dataset sources: EEG Motor Movement/Imagery Dataset (Schalk et al.) and Sleep-EDF Expanded (Kemp), under Open Data Commons Attribution v1.0. No private clinical recordings were used for this validation.

Research-use limitations

NeuroScope is a research preview. It does not diagnose epilepsy or other conditions. Data-integrity checks do not establish clinical validation, diagnostic accuracy, medical-device approval or privacy-compliance certification. Interpretations and downstream analysis remain outside the viewer’s scope.
